CHAPTER 1: PROJECT INTRODUCTION & PROBLEM STATEMENT

1.1 What is MAPD AI Mock Interview?

MAPD AI Mock Interview 2.0 is an intelligent, full-stack web application designed to help job seekers practice realistic technical and behavioral job interviews. Built with modern web standards, the platform simulates an actual hiring manager interview by combining voice interaction, real-time posture/eye-contact feedback, adaptive artificial intelligence follow-ups, and transcript-grounded performance evaluation.

The acronym MAPD stands for Mock AI Placement & Development. It transforms passive interview preparation (such as memorizing static textbook answers) into an active, immersive simulation where candidates speak out loud to an AI interviewer persona, receive follow-up probes based on their exact answers, and obtain an actionable performance scorecard graded against standard industry benchmarks like the STAR methodology (Situation, Task, Action, Result).

1.2 Why is it Needed? What Problem Does it Solve?

Engineering students and job seekers face significant hurdles when preparing for technical placements:

  • High Cost of Professional Coaching: Human mock interview services (like Interviewing.io or Pramp) charge between $100 and $250 per hour, making frequent practice inaccessible for most college students.
  • Passive Learning Inefficacy: Reading code or memorizing questions does not prepare candidates for the pressure of speaking fluently, maintaining composure, and explaining technical architectures under time constraints.
  • Lack of Objective, Immediate Feedback: Peer practice often results in subjective, unhelpful advice ("You did okay"). Candidates rarely learn their exact filler-word count (saying "um", "like", "you know"), technical depth score, or how to structure answers using the STAR method.
  • Generic, One-Size-Fits-All Questions: Most online quizzes ask generic questions regardless of whether the candidate is applying for a Frontend Developer, Backend Spring Boot Engineer, DevOps Specialist, or Data Scientist.
💡 Viva Voice Pitch (Memorize this for your examiners):
"My project is an AI Mock Interview platform that bridges the gap between passive learning and real-world placement interviews. It dynamically generates an 8-phase structured technical interview based on the candidate's target job role and resume, conducts the session in real-time using browser speech synthesis and recognition, monitors camera posture and eye-contact, asks adaptive follow-ups using Google Gemini 1.5 Flash, and delivers a zero-hallucination scorecard with verbal filler analysis and model STAR answers."

1.3 Who Can Use This System?

  1. College Students & Freshers: Preparing for on-campus placements, building verbal confidence, and practicing entry-level software engineering fundamentals.
  2. Experienced Engineers: Practicing system design scenarios, cloud architecture questions, and behavioral leadership rounds.
  3. College Placement Cells & Bootcamps: Automating large-scale student placement readiness assessments without needing hundreds of human evaluators.
  4. Technical Recruiters: Reviewing recorded candidate interviews and automated scorecards before scheduling final round panel interviews.

1.5 Benefits & Current Limitations

Core Engineering Strengths:

  • Zero Latency Speech & Vision: Because speech recognition, text-to-speech, and face tracking run inside the user's browser, there is zero per-minute audio streaming cost and no server network lag.
  • Zero-Hallucination Feedback: The post-interview evaluation uses deterministic transcript matching rather than trusting a black-box LLM to make up scores. If the candidate never spoke a keyword, it is flagged as missing.
  • High Reliability with Fallback Systems: If the Gemini API key runs out of quota, the system falls back to a deterministic 13-domain role engine without breaking the user's interview.

Honest Academic Limitations:

  • Browser Dependency: Speech recognition relies on Chrome's webkitSpeechRecognition engine. Firefox does not natively support this API.
  • Simplified Vision Heuristics: The posture tracking uses fast HTML5 Canvas 2D RGB skin pixel centroids rather than a heavy neural network like MediaPipe or OpenCV.

2.1 Five-Point Deep-Dive for Every Technology

1. Next.js 15 (App Router)

  • What it is: A production React framework by Vercel offering server-side rendering (SSR), static site generation (SSG), and integrated serverless API routes.
  • Why this project uses it: It combines both the frontend React client and the backend serverless endpoints in one unified TypeScript repository, completely eliminating cross-origin CORS errors.
  • Which files use it: app/layout.tsx, app/page.tsx, app/(routes)/*, and all API routes under app/api/*.
  • Real-world analogy: A modern smartphone operating system that runs user apps on screen while seamlessly handling background network sync in the background.

2. Convex Serverless Database

  • What it is: A modern reactive document database designed specifically for TypeScript applications that streams real-time updates over WebSockets.
  • Why this project uses it: In traditional databases, if an interview status updates, the frontend must continuously poll the server via HTTP. In Convex, the frontend hook useQuery(api.Interview.GetInterviewQuestions) re-renders automatically the instant any record changes.
  • Which files use it: convex/schema.ts, convex/Interview.ts, convex/users.ts.
  • Real-world analogy: A shared Google Doc where edits made by one person appear immediately on everyone's screen without clicking "Refresh".

3. Clerk Authentication

  • What it is: A managed user identity and access management (IAM) service.
  • Why this project uses it: It provides pre-built, secure login/signup dialogs, handles password hashing, OAuth callbacks, and verifies session tokens through Next.js middleware.
  • Which files use it: middleware.ts, app/Provider.tsx, app/(auth)/*.
  • Real-world analogy: A high-security building keycard badge that automatically opens authorized doors and keeps unauthorized guests outside.

4. Google Gemini 1.5 Flash

  • What it is: Google's high-speed multimodal generative AI model optimized for low-latency reasoning and conversational probing.
  • Why this project uses it: During an interview, the candidate is waiting for the next question. Gemini 1.5 Flash returns responses in under 800 milliseconds via HTTP POST, allowing natural back-and-forth conversational rhythm.
  • Which files use it: lib/roleInterviewerEngine.ts, app/api/generate-followup-question/route.tsx.
  • Real-world analogy: A sharp, attentive hiring manager who catches a specific keyword in your answer (like "Docker") and immediately asks, "How did you optimize your Docker container size?"

5. Web Speech API (Synthesis & Recognition)

  • What it is: The native JavaScript browser API for voice synthesis (TTS) and speech-to-text recognition (STT).
  • Why this project uses it: It requires zero paid third-party API keys, runs directly on candidate device hardware, and delivers instant verbal transcription.
  • Which files use it: app/(routes)/interview/[interviewId]/start/page.tsx, utils/interviewerConfig.ts.
  • Real-world analogy: The human ears and vocal cords built directly into the candidate's browser window.

6. HTML5 Canvas 2D Vision Telemetry

  • What it is: A low-level browser graphics API that allows reading and manipulating pixel arrays from video elements.
  • Why this project uses it: By downsampling the webcam stream to 320x240 pixels and calculating skin-tone coordinate centroids, the app measures candidate posture stability and head centering every 1000ms with negligible CPU consumption.
  • Which files use it: utils/facialAnalysis.ts.
  • Real-world analogy: A virtual interview coach sitting beside you, gently tapping your shoulder if you slouch or look away from the camera.

CHAPTER 6: BACKEND & SERVERLESS BUSINESS LOGIC

6.1 What is the Backend in this Project?

A common misconception for beginners is assuming every web application must have a separate Python Django or Node Express backend server running on a separate port (like localhost:5000).

In this project, the backend is a modern Serverless Monolith:

  • Next.js 15 Serverless API Routes (app/api/*): Next.js runs on a Node.js serverless execution environment. Every subfolder containing a route.ts or route.tsx file acts as an independent, scalable REST endpoint that executes on demand and scales down to zero when idle.
  • Convex Serverless Functions (convex/*): Convex runs cloud TypeScript functions on its reactive backend. It provides mutations (functions that write data) and queries (functions that read data) with end-to-end type safety.

6.2 API Route Handlers Explained

In Next.js App Router, an API route is defined by exporting asynchronous functions named after HTTP methods (e.g., POST, GET, DELETE): 

import { NextRequest, NextResponse } from "next/server";

export async function POST(req: NextRequest) {
    try {
        const body = await req.json(); // Parses incoming JSON
        // Execute business logic...
        return NextResponse.json({ status: 200, message: "Success" });
    } catch (error: any) {
        return NextResponse.json({ error: error.message }, { status: 500 });
    }
}

6.3 Convex Queries vs. Mutations

Concept Defined With Database Action Client Hook Example in Project
Query query({ handler: async (ctx, args) => ... }) Read-Only (pure function, cached, reactive) useQuery(...) api.Interview.GetInterviewQuestions
Mutation mutation({ handler: async (ctx, args) => ... }) Write / Update / Delete (atomic transaction) useMutation(...) api.Interview.SaveInterviewQuestion

6.4 Input Validation & Error Handling

The backend rigorously validates inputs before executing sensitive operations:

  • Authentication Checks: In routes like /api/upload-recording, the code calls await currentUser() from Clerk. If no user session is present, it immediately rejects the request with HTTP 401 Unauthorized.
  • File Type & Size Checks: In CreateInterviewDialog.tsx and /api/generate-interview-questions, the system verifies that uploaded resumes have the MIME-type application/pdf and a size under 10 megabytes.
  • Error Status Codes: Uses standardized HTTP codes: 200 (OK), 400 (Bad Request), 401 (Unauthorized), 403 (Forbidden), 429 (Rate Limit Exceeded), and 500 (Internal Server Error).

CHAPTER 7: DATABASE DEEP DIVE (CONVEX SCHEMA)

7.1 Which Database Technology is Used and Why?

The project uses Convex, an event-driven serverless document database. It is selected over traditional relational SQL databases (like MySQL/PostgreSQL) and traditional NoSQL databases (like MongoDB) because:

  1. Zero-Config Real-Time Sync: The database communicates with the frontend via persistent WebSockets. When feedback is saved, the dashboard re-renders instantly without needing custom WebSocket servers or manual polling.
  2. End-to-End TypeScript Validation: The database schema is defined directly in TypeScript (convex/schema.ts). Convex automatically generates client-side types, catching schema bugs at compile time.
  3. Integrated Cloud Object Storage: Convex provides built-in file storage (ctx.storage.generateUploadUrl), eliminating the absolute necessity of external S3 buckets for simple file persistence.

7.2 Detailed Database Schema Analysis

Here is the exact schema defined in [`convex/schema.ts`](file:///c:/Users/Deekshitha%20P/Documents/AI-Mock-Interview-2.0-main/convex/schema.ts): 

import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
    // Table 1: User Profiles
    UserTable: defineTable({
        name: v.string(),
        imageUrl: v.string(),
        email: v.string(),
    }),

    // Table 2: Interview Sessions
    InterviewSessionTable: defineTable({
        interviewQuestions: v.any(),                       // Array of 8-phase questions
        resumeUrl: v.union(v.string(), v.null()),          // Public URL of PDF resume
        userId: v.id('UserTable'),                         // Foreign Key pointing to UserTable._id
        status: v.string(),                                // 'draft' | 'completed'
        jobTitle: v.union(v.string(), v.null()),           // Target Job Role
        jobDescription: v.union(v.string(), v.null()),     // Job description requirements
        experienceLevel: v.optional(v.union(v.string(), v.null())), // e.g., '1–2 years'
        techStack: v.optional(v.union(v.string(), v.null())),       // e.g., 'React, Next.js'
        feedback: v.optional(v.any()),                     // Complete evaluation JSON
        recordingUrl: v.optional(v.union(v.string(), v.null())),    // Cloud video URL
        recordingId: v.optional(v.union(v.string(), v.null())),     // Storage file identifier
        recordingStorageId: v.optional(v.union(v.string(), v.null())),
        fileSize: v.optional(v.union(v.number(), v.null())),        // Size in bytes
        durationSeconds: v.optional(v.union(v.number(), v.null())), // Video length
        storageProvider: v.optional(v.union(v.string(), v.null())), // 'supabase' | 'convex' | 'imagekit' | 'server'
        questionTimestamps: v.optional(v.any()),           // Array mapping question index to video seconds
        candidateAnswers: v.optional(v.any()),             // Transcribed speech answers
        weakTopics: v.optional(v.any()),                   // Identified weakness categories
        interviewerGender: v.optional(v.union(v.string(), v.null())) // 'male' | 'female'
    })
});

7.3 Table Relationships (1-to-Many Architecture)

The relationship between users and interview sessions is a classic One-to-Many (1:N) relationship: 

[ UserTable ] (One User)
      │
      │ 1
      │
      ▼ N
[ InterviewSessionTable ] (Many Interview Sessions)
  Foreign Key: userId ──► References UserTable._id
  • A candidate creates an account once, generating one record in UserTable with a unique Convex ID (e.g., "jh72f8...").

8.1 Fundamental Networking Concepts

  • API (Application Programming Interface): A standardized contract that allows two software components (e.g., frontend React client and backend server) to communicate.
  • REST (Representational State Transfer): An architectural style that uses standard HTTP methods (GET, POST, DELETE) and endpoints (URIs) to transfer representations of resources.
  • JSON vs. FormData:
    • JSON (JavaScript Object Notation): Lightweight text format for transferring structured data (e.g., { "jobTitle": "DevOps" }).
    • FormData: Multipart MIME format (multipart/form-data) required when transmitting raw binary files (such as PDF resumes or video recordings) alongside text fields.

12.3 HTML5 Canvas 2D Vision Telemetry

Unlike heavy AI vision models that require downloading 50MB tensor weights, MAPD implements an ultra-fast (<2ms) frame-sampling heuristic in [`utils/facialAnalysis.ts`](file:///c:/Users/Deekshitha%20P/Documents/AI-Mock-Interview-2.0-main/utils/facialAnalysis.ts):

  1. Every 1000ms, an in-memory <canvas> draws the current webcam frame downscaled to 320x240 pixels.
  2. The function extracts the raw RGBA pixel buffer using ctx.getImageData().
  3. It computes average pixel luminance: 
    const lum = 0.299 * r + 0.587 * g + 0.114 * b;
    If average luminance is below 45, it flags "Too Dark"; if above 210, it flags "Overexposed".
  4. It identifies skin pixels using RGB ratio heuristics (r > 60 && g > 40 && r > g) and calculates the centroid center-of-mass (skinCenterX, skinCenterY). If the centroid drifts too far from the center, it warns the user: "Looking Away" or "Slight Tilt".

12.4 Dual-Tier Video Storage Architecture

Streaming high-definition video over unpredictable home internet connections often leads to packet loss. MAPD solves this using a dual-tier storage design:

       │
       ▼ (2. Background chunk upload after interview)
[ Next.js Serverless Route: /api/upload-recording ]
       │

`useEffect` runs side effects after a component renders. In `start/page.tsx`, it initializes the question countdown timer and starts speech recognition when the interviewer finishes speaking.

Q25. What is a controlled component in React?

Q26. What does `e.preventDefault()` do in `onSubmit`?

Q27. How does client-side routing work in Next.js?
Using `useRouter()` (e.g., `router.push('/interview/' + interviewId)`). It transitions pages by fetching the required component chunks via JavaScript without requesting a complete new HTML document from the server.

A folder wrapped in brackets like `[interviewId]`. Next.js extracts this URL parameter and passes it to the page component so it can fetch the specific interview session matching that ID.

Category 4: Backend & Serverless APIs

Q33. Where are your backend API routes located?
Inside `app/api/*`. Each subfolder contains a `route.ts` or `route.tsx` file exposing serverless handlers like `export async function POST(req: NextRequest)`.
Q34. What is a serverless function?
A backend function that executes on-demand in an isolated container. It automatically boots up when an HTTP request arrives and terminates when the response is sent, requiring zero ongoing server maintenance.
Q35. Why does `generate-interview-questions` use FormData instead of JSON?
Because the user can attach a binary PDF resume file. JSON cannot natively carry raw file byte streams, whereas `multipart/form-data` handles both file buffers and text fields in one request.
Q36. How do you extract files from `NextRequest`?
By calling `const formData = await req.formData()` and then `const file = formData.get('file') as File`.
Q37. What is the purpose of `NextResponse.json()`?
It is a Next.js helper that serializes a JavaScript object into a JSON string and sets the HTTP `Content-Type: application/json` header along with the appropriate status code.
Q38. What HTTP status code is returned when a user has no remaining rate limit?
HTTP 429: Too Many Requests.
Q39. What HTTP status code is returned when an unauthenticated user calls `upload-recording`?
HTTP 401: Unauthorized.
Q40. How is CORS handled in this project?
Because the Next.js frontend and API routes reside on the exact same domain origin, standard browser requests are same-origin, completely eliminating CORS configuration issues.
Q41. What does the `generate-followup-question` endpoint do?
It receives the current question and the candidate's spoken answer, calls the Google Gemini 1.5 Flash API, and returns an adaptive probing follow-up question.
Q42. What does the `delete-recording` endpoint do?
It verifies user ownership and permanently removes the video file from Supabase storage or server disk storage.

Category 5: Database & Convex BaaS

Q43. What is Convex?
Convex is a reactive serverless document database and backend-as-a-service. It synchronizes data in real time with the React frontend over persistent WebSockets.
Q44. What are the two main tables in your Convex schema?
`UserTable` (storing user profile name, email, avatar) and `InterviewSessionTable` (storing questions, answers, feedback, and video recording URLs).
Q45. How are the two tables linked?
Through a foreign key: `userId: v.id('UserTable')` in `InterviewSessionTable` points directly to the `_id` of the user in `UserTable`.
Q46. What is the difference between a Convex Query and Mutation?
A Query is a read-only, cached, reactive function that returns data (e.g., `GetInterviewQuestions`). A Mutation is a transactional function that writes or updates records in the database (e.g., `SaveInterviewQuestion`).
Q47. How does Convex achieve real-time synchronization?
Through WebSockets. When a client calls `useQuery`, Convex establishes a subscription. Whenever a mutation updates a record, Convex automatically pushes the new data to all active clients without HTTP polling.
Q48. Where are the Convex backend functions defined in the codebase?
Inside the `convex/` directory: `convex/schema.ts` (schema), `convex/Interview.ts` (interview logic), and `convex/users.ts` (user logic).
Q49. How do you prevent unauthorized users from viewing someone else's interview?
In `convex/Interview.ts`, `GetInterviewQuestions` verifies that `record.userId === args.uid`. If unauthorized, it logs a warning and returns `null`.
Q50. How is an interview session created in Convex?
By calling `await saveInterviewQuestion({ questions, resumeUrl, uid, jobTitle, ... })` which inserts a row into `InterviewSessionTable` with `status: 'draft'`.
Q51. How is interview feedback updated in the database?
Via the `UpdateFeedback` mutation in `convex/Interview.ts`, which patches the session record with the evaluation JSON and marks `status: 'completed'`.
Q52. Does Convex use SQL or NoSQL?
It is a document-based database (similar to NoSQL) but provides relational integrity through strongly typed foreign keys and strict TypeScript schema validators (`v.string()`, `v.id()`).
Q53. How do you generate Convex client types?
Running `npx convex dev` automatically generates client types into `convex/_generated/` whenever `schema.ts` is modified.
Q54. How do you inspect database records during development?
By running `npx convex dashboard`, which opens a visual database table browser in the web browser.

Category 6: Artificial Intelligence & Prompt Engineering

Q55. Which AI model is used in this project?
Google Gemini 1.5 Flash (`gemini-1.5-flash`).
Q56. Why use Gemini 1.5 Flash instead of Gemini 1.5 Pro or GPT-4?
Gemini 1.5 Flash is optimized for high-speed, low-latency conversational tasks. It responds in under 800ms, making it ideal for real-time interview pacing, while maintaining a generous free-tier API quota.
Q57. How is Gemini called in the code?
Via an Axios HTTP POST request in `lib/roleInterviewerEngine.ts` to `https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent?key=${apiKey}`.
Q58. How do you enforce that Gemini returns valid JSON?
The system prompt explicitly commands: "Respond with ONLY a raw JSON object (no markdown, no backticks)". The code also applies a regex cleanup (`replace(/```json/g, '').replace(/```/g, '')`) before calling `JSON.parse()`.
Q59. What happens if Gemini API call times out or fails?
The Axios call has a 7000ms timeout. If it errors, a `catch` block catches the exception and falls back to a deterministic, keyword-matching role intelligence engine. The interview never freezes.
Q60. How does the AI handle candidates who say "I don't know"?
The prompt specifically checks for struggle phrases like "I don't know". Gemini responds with a gentle pivot question: "No worries! Let's shift our focus to another area..." to keep candidate confidence high.
Q61. What are the 13 engineering domains recognized by the engine?
Java Developer, Python Developer, Frontend Developer, Backend Developer, Fullstack Developer, AI/ML Engineer, Data Scientist, Data Analyst, DevOps Engineer, Cloud Engineer, QA Engineer, Cybersecurity Engineer, and General Software Engineer.
Q62. How does the engine generate questions for unknown or custom roles?
`normalizeRole()` analyzes the combined role and tech stack string. If no specialized domain matches, it defaults to `software_engineer` and dynamically injects the candidate's exact tools into progressive scenario templates.
Q63. Does the post-interview scoring use Gemini?
No. Post-interview feedback is computed using a deterministic text-matching and regex algorithm in `app/api/interview-feedback/route.tsx`. This guarantees zero hallucinations in scoring.
Q64. How are verbal filler words counted?
Using regular expressions that match conversational fillers like `(um|uh|like|you know|basically|actually)` across the transcribed answer array.

Category 7: Audio, Video & Computer Vision

Q65. How does the application access the user's camera and microphone?
Using `navigator.mediaDevices.getUserMedia({ video: true, audio: true })`. The browser prompts the user for permission.
Q66. Which API records the interview video?
The browser `MediaRecorder` API. It records chunks of video in WebM format (`video/webm; codecs=vp8,opus`).
Q67. Why use IndexedDB for local video buffering?
Video files are large (20MB-100MB). LocalStorage is limited to 5MB and blocks the main thread. IndexedDB allows asynchronous, persistent storage of large binary Blobs, ensuring the video is safe even if the network drops.
Q68. How does the Canvas 2D posture tracking work?
Every 1000ms, a hidden 320x240 canvas draws the video frame, samples pixel RGBA values, detects skin-color centroids, and measures whether the candidate's face is centered or tilted.
Q69. How does the app check if lighting is adequate?
It calculates perceived luminance across sampled pixels: `0.299*R + 0.587*G + 0.114*B`. If average luminance is below 45, it flags "Too Dark"; if above 210, it flags "Overexposed".
Q70. How does synchronized question playback work?
When each question starts, the current video recording elapsed time (in seconds) is saved to `questionTimestamps`. On the playback screen, clicking a question sets `video.currentTime = timestamp`, instantly jumping to that answer.

Category 8: Authentication, Security & Deployment

Q71. How are private routes protected in Next.js?
Via `middleware.ts` using Clerk's `clerkMiddleware()`. It intercepts requests to `/dashboard` and `/interview` and forces an automatic redirect to `/sign-in` if no valid JWT session token exists.
Q72. What is Arcjet and how is it used?
Arcjet is a security SDK that provides bot detection and rate limiting. It uses a token-bucket algorithm to protect expensive API endpoints from abuse.
Q73. Why should API keys never be stored in GitHub?
Public repositories are scanned by bots within seconds. Leaked keys can result in stolen user data, massive cloud billing charges, or account suspension.
Q74. What is the purpose of `.env.example`?
It provides a safe, shareable template showing which environment variable names are required without revealing actual secret keys.
Q75. How do you deploy this application to production?
Push the code to GitHub, deploy the Convex backend using `npx convex deploy`, import the repo into Vercel, configure production environment variables, and update Clerk redirect URLs.
Q76. What is Continuous Deployment (CD)?
Whenever you run `git push origin main`, Vercel automatically detects the new commit, runs `npm run build`, and updates the live production site without manual server intervention.
Q77. What happens if an uploaded video exceeds Vercel's 4.5MB serverless payload limit?
The app supports direct cloud upload via signed URLs (Convex / Supabase) bypassing the Vercel serverless function payload limit entirely.
Q78. What is the difference between client-side validation and server-side validation?
Client-side validation (in React) provides instant user feedback (e.g., "Field cannot be empty"). Server-side validation (in API route) is essential for security because malicious users can bypass frontend forms by sending direct curl/HTTP requests.
Q79. How is candidate privacy protected regarding webcam recordings?
Recordings are stored only under the candidate's authenticated user ID. In `api/delete-recording`, candidates can permanently delete their cloud video files at any time.
Q80. What would you do if a database query is running slow?
Add database indexes on frequently queried fields (such as `userId` in `InterviewSessionTable`) to reduce table scan time from O(N) to O(log N).

AI Mock Interview 2.0 (MAPD) is an end-to-end full-stack web application developed with Next.js 15.4 (App Router), React 19, TypeScript, and Convex Reactive Document DB.
